# 스트리머용 로컬 자립형 봇 — 설계 문서 v0.3

> v0.3 구현 현황: M0, M1(읽기 전용), **M2 신청곡+스테이션**, **M3 룰렛** 구현 완료. 미구현: 공식 API 연결(봇 채팅 송신), 볼륨 ReplayGain, 공개 신청곡 페이지, 후원 알림 오버레이, 트레이 아이콘.

> 코드명: **`LocalBot`** (가칭) · 레퍼런스: 뚜봇, 나디아봇, 빵떡
> v0.2 변경: 치지직 우선, Windows 전용, 오픈소스로 확정. 핵심 기능 3개(신청곡 스테이션, 룰렛, 스탠드얼론)를 상세 설계에 반영.

## 0. 확정 사항

| 항목 | 결정 |
|---|---|
| 플랫폼 | **치지직 먼저**. SOOP 등은 어댑터 자리만 남겨 둠 |
| OS | **Windows 10/11 (x64)** |
| 배포 | **오픈소스** (라이선스는 MIT 제안, §9) |
| 이게 없으면 안 쓰는 기능 | ① **절대 고장 안 나는 스테이션형 신청곡 플레이리스트** ② **손쉬운 룰렛** ③ **완벽한 스탠드얼론** |

이 세 가지가 제품의 정체성입니다. 나머지(명령어, 알림, 포인트 등)는 **세 기능을 해치지 않는 범위에서만** 넣습니다.

## 1. 한 줄 정의

**`LocalBot.exe` 하나만 실행하면 되는 치지직 봇.** 신청곡 라디오 스테이션과 룰렛이 핵심이고, 외부 서버·회원가입·API 키 없이 동작합니다.

**원칙**
1. **서버가 유일한 진실의 원천.** 큐, 현재 곡, 재생 위치, 룰렛 결과는 모두 서버(SQLite)가 갖습니다. 오버레이와 플레이어는 상태를 그리기만 하는 단말이라서 꺼졌다 켜지면 서버에서 스냅샷을 받아 그대로 이어서 합니다.
2. **결과는 서버에서 먼저 정하고, 연출은 나중에 합니다.** 룰렛 결과는 애니메이션이 돌기 전에 이미 DB에 기록됩니다.
3. **모든 것은 실패한다고 가정합니다.** 네트워크, YouTube, OBS, 워커 프로세스 각각에 복구 경로를 둡니다.

## 3. ① 신청곡 + 스테이션 (최우선 기능)

### 3.1 개념

```
        ┌──────────── 재생 우선순위 ────────────┐
        │ 1. 우선 신청곡 (후원 신청 등)            │
        │ 2. 일반 신청곡 (선착순)                  │
        │ 3. 스테이션 (큐가 비면 자동 재생) ◀── 무음 방지 │
        │ 4. 로컬 비상 스테이션 (YouTube 불가 시)   │
        └────────────────────────────────────────┘
```

- **스테이션** = 신청곡이 없을 때 자동으로 흐르는 "라디오". 방송 중에 음악이 끊기지 않게 합니다.
  - 소스: 스트리머가 만든 플레이리스트 / YouTube 재생목록 가져오기 / **로컬 음악 폴더**(mp3, ogg, flac 등) / **자동 생성 "인기 신청곡"**(끝까지 재생되고 스킵되지 않은 신청곡이 자동으로 쌓임)
  - 여러 스테이션을 만들고 하나를 골라 틉니다 (예: "잔잔", "게임 중", "새벽").
  - 재생 방식: 순차 / 셔플 / 가중 셔플. **최근 N곡은 다시 안 나옴**(기본 20곡).
- **신청곡이 들어오면**: 기본은 지금 흐르는 스테이션 곡이 끝난 뒤 신청곡 재생. 옵션으로 "즉시 전환(페이드아웃 3초)".
- **신청곡 큐가 다 비면**: 스테이션이 이어서 재생합니다. 스테이션 위치는 기억합니다.

### 3.2 신청 방법

| 방법 | 기본값 | 비고 |
|---|---|---|
| `!신청곡 <YouTube 링크>` | ON | 링크·ID·shorts·music.youtube 형식 모두 파싱 |
| 후원 메시지에 링크 포함 | ON | 금액 조건 충족 시 **우선 신청** |
| `!신청곡 <검색어>` | OFF | API 키 없이는 안정적인 검색이 불가능 → YouTube Data API 키를 넣었을 때만 켜짐 (스탠드얼론 원칙 유지) |
| 대시보드 직접 추가 | ON | 스트리머·매니저용 |

**채팅 명령어**: `!신청곡` `!현재곡` `!대기열` `!내신청` `!신청취소`
**매니저 명령어**: `!스킵` `!일시정지` `!재생` `!볼륨 50` `!신청마감` `!신청오픈`

**신청 정책** (대시보드에서 토글)
- 최대 길이 (기본 8분), 1인 최대 대기 곡 수 (기본 2), 신청 쿨다운
- 중복 금지: 큐에 같은 곡 금지, 최근 N시간 안에 재생된 곡 금지
- 블랙리스트: 영상 ID / 채널 / 제목 키워드
- 신청 자격: 누구나 / 팔로워 / 구독자 / 매니저 / 후원 N원 이상
- 승인 모드: 신청곡이 바로 큐에 들어가지 않고 "승인 대기"에 쌓임

### 3.3 재생기 구조

- **플레이어 = OBS 브라우저 소스 `/o/player`** (화면에 안 보여도 되는 오디오 전용 소스). 음악 소리는 OBS가 직접 캡처하므로 데스크톱 오디오와 섞이지 않습니다. *("OBS에서 오디오 제어" 체크)*
- YouTube 곡은 **IFrame Player API**로, 로컬 곡은 HTML5 `<audio>`로 재생합니다. 둘 다 같은 플레이어 안에 있습니다.
- **마스터 리스(lease)**: 플레이어가 OBS와 대시보드 미리보기 등 여러 곳에 열려 있어도 **소리를 내는 건 하나뿐**입니다. 먼저 리스를 잡은 쪽이 마스터가 되고, 나머지는 모니터가 됩니다. 이중 재생을 막습니다.

### 3.4 "절대 고장 안 나는" 장치들

| # | 장애 상황 | 대책 |
|---|---|---|
| 1 | 삭제·비공개·**퍼가기 금지**·지역 제한 영상 신청 | **신청 시 1차 검증**: oEmbed 조회(존재 여부, 퍼가기 가능 여부). **재생 전 2차 검증**: 플레이어가 다음 곡을 숨은 음소거 플레이어로 미리 로드(prefetch)해서 재생 가능 여부와 실제 길이를 확인 → 실패하면 재생 차례가 오기 **전에** 자동으로 빼고 신청자에게 채팅으로 알림 (포인트 신청이면 환불) |
| 2 | 재생 중 멈춤 (버퍼링 무한, 프리즈) | **워치독**: 플레이어가 1초마다 `{state, currentTime}` 하트비트 전송. 재생 중인데 위치가 8초 넘게 안 움직이면 → 같은 위치로 재로드 → 다시 실패하면 스킵 + 사유 기록. 곡 시작 직후 광고나 로딩 구간을 감안해 첫 진행 감지까지 유예 시간을 따로 둠 (기본 45초) |
| 3 | 재생 중 에러 (YouTube 에러 2/5/100/101/150) | 즉시 다음 곡으로 넘어가고 해당 곡에 "재생 불가" 표시. 스테이션 곡이면 스테이션에서 자동 비활성화 |
| 4 | OBS 재시작, 소스 새로고침, 장면 전환으로 소스 언로드 | 서버가 재생 위치를 2초마다 저장 → 플레이어가 다시 연결되면 **같은 곡 같은 위치에서 재개** |
| 5 | LocalBot 워커 크래시 | Supervisor가 1초 안에 재시작 → 큐와 위치를 DB에서 복원 → 플레이어는 자동 재연결 |
| 6 | 인터넷 끊김, YouTube 전체 장애 | YouTube 곡이 3곡 연속 실패하거나 네트워크가 끊기면 **로컬 비상 스테이션**(로컬 음악 폴더)으로 자동 전환. 복구되면 원래 큐로 복귀 |
| 7 | 플레이어 소스가 아예 없음 (OBS 꺼짐) | 하트비트가 10초 끊기면 대시보드에 빨간 경고 표시. 큐는 멈춘 상태로 보존(곡이 그냥 넘어가지 않음) |
| 8 | 같은 명령이 두 번 처리됨 (재연결 중 중복) | 모든 명령에 시퀀스 번호를 붙여 멱등 처리. 플레이어는 재연결할 때 전체 스냅샷부터 받음 |
| 9 | 매니저 실수 (잘못 스킵, 큐 삭제) | **되돌리기**: 최근 20개 조작 되돌리기 가능 |
| 10 | 볼륨이 곡마다 들쭉날쭉 | 로컬 곡은 ReplayGain 분석. YouTube 곡은 곡별 볼륨 기억 (매니저가 조정하면 저장) |

**검증 방법**: "카오스 테스트"를 자동 테스트로 둡니다. 가짜 플레이어로 위 1~8번 상황을 강제로 만들어, 음악이 끊기지 않고 큐가 깨지지 않는지 CI에서 매번 확인합니다.

### 3.5 화면

- **대시보드 → 신청곡 탭**: 현재 곡(진행 바, 스킵, 일시정지, 볼륨), 큐(드래그 정렬, 위로 올리기, 삭제), 승인 대기, 스테이션 선택, 신청 ON/OFF, 재생 이력
- **오버레이 `/o/nowplaying`**: 곡 제목, 신청자, 진행 바 (테마 선택 가능)
- **오버레이 `/o/queue`**: 다음 N곡 목록
- **공개 신청곡 목록 페이지** (선택, v1+): 시청자가 대기열을 볼 수 있는 읽기 전용 페이지. 단, 로컬이라 외부 공개는 하지 않습니다 (§5 참조)

> ⚠️ **알려진 한계**: YouTube 임베드에서 나오는 광고는 제어할 수 없습니다. 영상을 다운로드해서 재생(yt-dlp 등)하는 방식은 YouTube 약관 문제와 잦은 고장 때문에 **채택하지 않습니다**.

## 4. ② 손쉬운 룰렛

### 4.1 "손쉬운"의 기준 = **30초 안에 룰렛 하나 완성**

```
[1단계: 항목]                 [2단계: 언제 돌릴까]           [3단계: 모양]
 ┌──────────────────────┐     ○ 1,000원당 1회             ○ 기본 원판
 │ 노래 한 곡           │     ○ 정확히 3,333원 후원 시      ○ 슬롯머신
 │ 스쿼트 10개      x2  │     ○ !룰렛 명령어 (포인트)       ○ 카드 뽑기
 │ 꽝               x5  │     ○ 수동 (버튼만)              [미리보기 ▶]
 │ 시청자 소원 1개      │
 └──────────────────────┘
  → 실시간 원판 미리보기 + 각 항목 확률(%) 표시
```

- **한 줄에 항목 하나**. 뒤에 `x5`를 붙이면 가중치. 또는 항목마다 슬라이더로 조정.
- **템플릿**: "벌칙 룰렛", "꽝 많은 룰렛", "1/100 대박 룰렛" 등에서 골라 시작.
- **공유 코드**: 룰렛 설정을 문자열 하나로 내보내고 가져오기 → 스트리머끼리 공유.
- **테스트 버튼**: 방송 전에 "가짜 후원 5,000원"으로 실제처럼 돌려 보기.

### 4.2 트리거 규칙

| 규칙 | 동작 |
|---|---|
| **금액당 N회** | `floor(후원액 / 단가)`회. 1회 후원당 최대 횟수 상한(기본 10). **잔액 이월** 옵션: 시청자별로 남은 금액을 누적 (예: 500원 + 500원 = 1회) |
| **정확 금액** | 3,333원처럼 특정 금액일 때만. 금액마다 다른 룰렛 연결 가능 |
| **명령어** | `!룰렛 벌칙` + 포인트 차감 (포인트 기능 켰을 때) |
| **수동** | 대시보드 버튼 |

- 여러 룰렛이 동시에 해당하면 **정확 금액 > 금액당** 순으로 하나만 실행 (설정으로 "모두 실행"도 가능).

### 4.3 연출과 신뢰

- **결과는 서버가 `crypto.getRandomValues`로 먼저 뽑아 DB에 기록**한 뒤, 오버레이는 그 결과에 멈추도록 애니메이션만 재생합니다 → 새로고침이나 지연이 있어도 결과가 바뀌지 않습니다.
- **연속 회전**: 10회가 한 번에 나오면 원판을 10번 돌리지 않고, 1번 빠르게 돌린 뒤 결과 10개를 카드로 한꺼번에 보여줍니다.
- **대기열**: 룰렛끼리, 그리고 후원 알림과 겹치지 않게 "무대 큐"를 공유합니다 (설정으로 분리 가능).
- **결과 채팅**: `🎰 {user}님 룰렛 결과: {result}` (템플릿 수정 가능)
- **재고 항목**: "치킨 기프티콘 (1개 한정)" → 당첨되면 자동으로 빠짐.
- **이력과 통계**: 날짜·시청자·결과 기록, "오늘 꽝 확률 실측 37%" 등 → 조작 의혹이 나와도 바로 보여줄 수 있음.
- **미이행 벌칙 목록**: "스쿼트 10개" 같은 결과를 체크리스트로 관리 (완료 체크).

## 5. ③ 완벽한 스탠드얼론

### 5.1 정의 (이 체크리스트를 모두 지켜야 릴리스)

- [ ] **설치 없음**: 압축 풀고 `LocalBot.exe` 실행. 관리자 권한 불필요. 레지스트리 안 씀 (자동 시작은 사용자가 켤 때만 시작 프로그램 폴더 바로가기로)
- [ ] **런타임 없음**: Node, Python, .NET 설치 불필요 (Bun 단일 실행 파일로 컴파일)
- [ ] **포터블**: 모든 데이터는 exe 옆 `data/` 폴더. 폴더째 USB로 옮겨도 그대로 동작
- [ ] **우리 서버 없음**: 개발자가 운영하는 서버가 하나도 없음. 프로젝트가 사라져도 계속 동작
- [ ] **API 키 없음**: 핵심 기능(신청곡, 룰렛, 명령어, 알림)은 키 없이 동작. 키는 선택 기능(검색 신청 등)에만
- [ ] **에셋 내장**: 폰트, 기본 효과음, 테마, 대시보드가 exe 안에 들어 있음. CDN을 쓰지 않음
- [ ] **오프라인 내성**: 인터넷이 끊겨도 앱은 죽지 않음. 재연결을 기다리고, 로컬 스테이션은 계속 재생
- [ ] **자가 복구**: Supervisor가 워커를 감시하고 재시작. DB는 WAL + 방송 시작 때마다 자동 백업 (7개 보관)
- [ ] **업데이트는 선택**: GitHub Releases 확인만 하고 자동 설치는 안 함. 꺼도 됨

### 5.2 핵심 난제: 치지직 인증 🔑

치지직 공식 Open API는 **Client ID + Client Secret**이 필요합니다. 오픈소스 앱에 Secret을 넣어 배포하면 안 되고, 중계 서버를 두면 스탠드얼론 원칙이 깨집니다.

| 방식 | 설정 난이도 | 채팅 읽기 | 후원 수신 | 봇 채팅 송신 | 안정성 |
|---|---|:-:|:-:|:-:|---|
| **A. 내 앱 등록** (치지직 개발자센터에서 스트리머가 직접 앱 등록 → ID/Secret 입력) | 중 (첫 1회 5분, 마법사가 안내) | ● | ● | ● | 공식이라 제일 안정적 |
| **B. 읽기 전용 익명 연결** (공개 채팅 소켓 접속) | 없음 (채널 URL만 입력) | ● | ● | ✕ | 비공식이라 치지직이 변경하면 깨질 수 있음 |
| C. 중계 서버 | 쉬움 | ● | ● | ● | **스탠드얼론 위반 → 채택 안 함** |

**제안: A를 기본으로 하고, B는 "빠른 시작 + 비상 폴백"으로 씁니다.**
- 처음 켜면 채널 URL만 넣고 **B로 즉시 시작** → 신청곡(후원 신청)과 룰렛은 바로 동작
- 봇이 채팅으로 답하려면 마법사로 A를 설정
- A 연결이 끊기면 자동으로 B로 읽기를 유지 → **신청곡과 룰렛이 멈추지 않음** (봇 답장만 잠시 멈춤)

> ⚠️ **확인 필요 (M1 착수 전)**: ① 치지직 개발자센터 앱 등록에 심사가 있는지, `http://localhost` 리다이렉트를 허용하는지 ② Open API 세션 이벤트(채팅·후원)의 실제 필드 ③ 관리 기능(채팅 삭제·임시 제한) API가 있는지

### 5.3 Windows 고려 사항

- **SmartScreen 경고**: 서명되지 않은 exe는 "Windows의 PC 보호" 경고가 뜸 → 오픈소스 무료 코드 서명(예: SignPath Foundation) 신청. 그 전까지는 README에 안내
- **백신 오탐**: 단일 exe로 컴파일된 런타임은 오탐이 날 수 있음 → 릴리스마다 VirusTotal 결과 첨부, 빌드 재현 가능하게(GitHub Actions에서 빌드)
- **포트**: 기본 `7777`. 이미 쓰고 있으면 실행 시 알리고 설정에서 변경 (오버레이 URL이 바뀌면 안 되므로 자동 랜덤 포트는 쓰지 않음)
- **한글 경로**: `C:\Users\홍길동\...` 같은 한글·공백 경로에서 테스트 필수

## 6. 정규화 이벤트 모델

```ts
type Role = 'streamer' | 'manager' | 'subscriber' | 'follower' | 'viewer';

interface Viewer { platform: 'chzzk'; id: string; nickname: string; roles: Role[] }

type BotEvent =
  | { type: 'chat';     viewer: Viewer; text: string; msgId: string }
  | { type: 'donation'; viewer: Viewer | null; amountKRW: number;   // 치즈 1 = 1원
                        text?: string; kind: 'chat' | 'video' | 'mission' }
  | { type: 'subscription'; viewer: Viewer; months: number; tier?: string }
  | { type: 'stream';   state: 'online' | 'offline' }
  | { type: 'system';   level: 'info' | 'warn' | 'error'; message: string };

interface Envelope { id: string; ts: number; source: 'chzzk-official' | 'chzzk-readonly' | 'mock'; event: BotEvent }
```

- **중복 제거**: A와 B가 동시에 연결된 전환 구간에는 같은 후원이 두 번 들어올 수 있음 → `(시청자, 금액, 메시지, 시각±3초)` 해시로 중복 제거. **후원이 두 번 집계되면 룰렛이 두 번 돌기 때문에 필수.**

## 9. 기술 스택

## 10. 보안

- 기본 바인딩은 `127.0.0.1`. LAN 노출(예: 다른 PC의 OBS)은 옵션으로만, 켤 때 경고
- `Host` 헤더 검증(DNS rebinding 방지), 대시보드 세션 토큰, 변경 요청에 CSRF 토큰
- 오버레이는 위젯별 읽기 전용 키 (`/o/player?key=...`), 재발급 가능
- Client Secret과 토큰은 **Windows DPAPI**로 암호화 저장 (같은 Windows 계정에서만 복호화 가능)
- 채팅 텍스트와 곡 제목은 오버레이에서 항상 이스케이프 (XSS 방지)
